---
title: Stop or remove an installation
description: Choose whether to keep your data, identify the exact project resources, and remove only what you intend.
---

There is no `evestack uninstall` command. Choose the outcome first:

| Outcome | Action | Data retained |
| --- | --- | --- |
| Stop spending and pause work | Pause routines, disable triggers, stop the agent and dashboard | Database, code and configuration |
| Remove containers, keep the installation recoverable | Stop the agent, then take the correct Compose project down without `-v` | Database volume and project files |
| Permanently remove one installation | Verify a backup, remove its exact containers/volume, then its files | Only the backups you chose to retain |
| Reclaim shared disk space | Inspect images, caches and models individually | Depends on what you explicitly remove |

## 1. Identify the installation

Keep the project directory until you have identified its resources. The Compose
file's `name:` value ties the installation to its containers and volume. Preserve
that value when moving or recovering a project; do not derive a new name and
assume it refers to the same data.

For a generated project:

```bash
docker compose config --services
docker compose config --volumes
docker compose --profile dashboard ps -a
```

For an attached project, inspect the files first. If attach wrote
`docker-compose.evestack.yml` beside an existing Compose file, use it explicitly:

```bash
docker compose -f docker-compose.evestack.yml config --services
docker compose -f docker-compose.evestack.yml config --volumes
docker compose -f docker-compose.evestack.yml ps -a
```

Use that same `-f` choice on **every** subsequent Compose command. A bare
`docker compose` in an attached project may operate on the original application's
services and data. `config --volumes` lists logical volume keys; inspect Docker's
volume names and Compose labels to confirm the actual volume before deleting it.

<Warning>
  Docker's `--filter name=` matches substrings. It can select another application
  with a similar name. List resources, inspect their labels and remove by exact
  name. Never pipe a name-filter result into a deletion command.
</Warning>

## 2. Stop work and keep the data

Pause routines in the dashboard and disable inbound webhooks or bot delivery if
needed. Stop the agent through its terminal, systemd service or launchd job, and
prevent its supervisor from immediately starting it again. See
[Operations](/docs/operations#run-the-agent-as-a-service). Stopping a dashboard
alone does not stop the agent, existing model calls or its code-authored schedules.

For a generated project, stop the dashboard and database containers:

```bash
docker compose --profile dashboard stop
```

To also remove their containers and network while retaining named volumes:

```bash
docker compose --profile dashboard down
```

Neither command includes `-v`. Keep the project files and volume. Restarting the
installation later can resume durable work, so review pending jobs first.

An attached dashboard may be a standalone container started by the printed
`docker run` command. Compose does not manage it. Find it in the inventory and
stop its **exact** name separately:

```bash
docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
docker stop EXACT-DASHBOARD-CONTAINER
```

Replace the placeholder only after inspection. Do the same for any session
sandbox containers you intend to stop. A container's session or project labels
are stronger evidence than a similar-looking name.

## 3. Permanently remove this installation

First follow [Backup and restore](/docs/backup-restore). Verify a restore while
Postgres is still available. Decide whether you also need copies of agent code,
private configuration, skill files and files kept inside session sandboxes.

Then stop the agent and remove its exact dashboard/container resources. For a
**reviewed generated Compose project whose listed volumes all belong to this
installation**, this command also deletes its non-external volumes:

```bash
# Permanent deletion: run only after checking this project's services and volumes.
docker compose --profile dashboard down -v
```

For an attached project, use the reviewed `-f` file and inspect its contents.
Do not delete a shared or externally supplied database. Remove a standalone
attached dashboard by exact name after stopping it:

```bash
docker rm EXACT-STOPPED-DASHBOARD-CONTAINER
```

A deleted volume loses tasks, memories, approval/review history, routines,
notification attempts, budget policies and regression cases. A filesystem copy
of the project does not contain those database records.

Remove the project directory only after its resources and backups are accounted
for. Review private configuration backups under `~/.evestack/config-backups` as
well: `evestack configure` stores them outside the project, and they retain old
secrets. Select only backups belonging to the removed project; other projects
may use the same backup directory. Revoke provider tokens, bot credentials or
hosted OAuth connections that are no longer needed. Deleting local files does
not revoke them at the provider.

### If the project directory is already gone

Inspect the full inventory and each candidate's Compose labels or mount details:

```bash
docker volume ls
docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
docker volume inspect EXACT-VOLUME-NAME
docker inspect EXACT-CONTAINER-NAME --format '{{json .Mounts}}'
```

If ownership is uncertain, retain it until identified. Once confirmed, backed up
and detached from its intended containers, remove only the exact volume:

```bash
docker volume rm EXACT-CONFIRMED-VOLUME-NAME
```

A refusal because a container still references it is a reason to inspect that
container, not to force deletion.

## 4. Optional cleanup of shared resources

These belong to the host and may serve other projects. Leaving them installed
is a valid choice.

```bash
docker system df -v
docker images ghcr.io/sammytourani/evestack-dashboard
docker images pgvector/pgvector
docker images --filter 'reference=eve-sandbox-template:*'
ollama list
npm list -g --depth=0
```

Inspect dependencies before removing an exact image tag, stopped sandbox or
model. `pgvector/pgvector` is shared by applications beyond Eve Stack. Sandbox
images share most layers, so their displayed total sizes are not the space each
removal will recover. Avoid broad `docker system prune --volumes` commands.

The npm `~/.npm/_npx` cache is shared with every tool run through `npx`; removing
an installation does not require clearing it. If you installed the CLI globally
and no longer want it, `npm uninstall -g evestack` removes that CLI installation.
It does not remove project files or database volumes.
