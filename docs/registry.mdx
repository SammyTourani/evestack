---
title: The @evestack registry
description: Add individual Eve Stack components to an existing Eve project.
---

Use the registry when you want individual components in an Eve project. Use
[the CLI](/docs/cli) to create a complete workspace or attach its dashboard.
Registry items copy source files into your project; later registry changes do
not update those copies automatically.

```bash
eve registry add @evestack=https://raw.githubusercontent.com/SammyTourani/evestack/main/registry/r/{name}.json
eve registry view @evestack/memory
eve add @evestack/memory
```

Inspect an item's files, dependencies and installation notes before adding it.
Commit or back up your existing project, then review the resulting diff.

## Available components

| Item | Adds | Configuration still required |
| --- | --- | --- |
| `@evestack/memory` | `remember`, `recall` and `forget` tools plus the memory library | Postgres with pgvector, an embedding provider, and the intended owner scope |
| `@evestack/instrumentation` | OTLP trace export | Dashboard URL and ingest authentication; decide whether prompt/tool data should be exported |
| `@evestack/docker-sandbox` | Local Docker sandbox backend | Docker availability and a reviewed network/resource policy |
| `@evestack/basic-auth` | The Eve HTTP channel's authentication chain | Private `EVESTACK_AUTH_USER` and `EVESTACK_AUTH_PASSWORD` settings |
| `@evestack/channel-slack` | Slack channel wiring | Platform credentials and allowed senders |
| `@evestack/channel-telegram` | Telegram channel wiring | Platform credentials and allowed senders |
| `@evestack/channel-discord` | Discord channel wiring | Platform credentials and allowed senders |

Adding code does not prove an integration works. Follow [channel setup](/docs/channels)
and [the first useful task](/docs/first-task), then verify actual results and receipts.
Memory ownership and recall behavior are explained in [memory](/docs/memory).

### Replacing the stock authentication file

A stock Eve project already has `agent/channels/eve.ts`. The basic-auth item
preserves that file unless you explicitly allow replacement:

```bash
eve registry view @evestack/basic-auth
# After reviewing and backing up your existing authentication chain:
eve add @evestack/basic-auth --overwrite
```

Merge any custom authenticators deliberately. Production requests require the
configured credentials; local-development access follows Eve's process-level
`localDev()` policy. This item requires Eve 0.30 or later. It is exercised with
the current template's `^0.54.3` range; it is not a compatibility promise for
all later releases.

## Verified candidate installation

The September 16, 2026 rehearsal created a stock project with the Eve 0.54.3 CLI;
its declared `^0.54.3` dependency resolved to Eve 0.54.5. Using that installed CLI,
all seven current items installed, all ten target files matched `registry/r/`
byte for byte, and the project passed `tsc --noEmit` without adding path aliases.
The existing authentication file was preserved first, then explicitly replaced
in the disposable project.

A local HTTP fixture served the candidate registry files; third-party package
dependencies came from npm. Interactive setup was skipped. This checks package
installation and types, not a running Docker backend, authenticated channel or
live model. The candidate must still reach the public registry location when
its reviewed commit is merged.

## Source, dependencies and upgrades

`registry/build.mjs` builds seven items from the actual template source. It
checks that local imports resolve within each item's file list. CI checks that
generated files match source and that dependency ranges match the template.
The memory tools use relative imports so a stock project needs no extra aliases.

Items declare their own extra dependencies. They rely on the host Eve project's
`ai` dependency and override rather than installing a conflicting second version.
Read the emitted item for the current ranges:

```bash
node -e "console.log(require('./registry/r/memory.json').dependencies)"
```

The default URL follows `main` and can change. For a reproducible installation,
use a reviewed commit in the registry URL and record the resulting lockfile.
The URL must retain the literal `{name}` placeholder. If a namespace is already
configured, `eve registry add` preserves it; review `package.json` before changing
the mapping. Fetching successfully does not authenticate a third-party mirror.

For upgrades, compare your installed files with the reviewed source and merge
changes explicitly. Do not overwrite modified authentication, channel or memory
code without reviewing its configuration and data implications. See
[upgrading](/docs/upgrading) and [backup and restore](/docs/backup-restore).
