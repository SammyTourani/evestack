Eve Stack gives a technical operator one workspace to run AI tasks, inspect their results,
answer tool decisions and schedule tested work. It packages the eve agent framework with
Postgres history, a dashboard and the tools needed to operate it yourself.

Start with a **repository maintenance brief**: connect one repository, ask what changed and
what needs attention, then check the cited evidence. Once the result is useful, save the
request as a routine and test it before enabling repeats.

## What the workspace does

| Surface | What you can do |
| --- | --- |
| Today | See pending decisions, recent tasks, routine state and setup checks |
| Tasks | Start work, read results, continue a conversation and inspect recorded evidence |
| Routines | Preview a timezone-aware schedule, run a test, enable repeats and review history |
| Connections | Check account authorization and prepare a task for the selected repository |
| Knowledge | Inspect remembered facts, propose corrections and review installed skills |
| Settings | Verify configuration, manage opted-in budgets and inspect notification delivery |
| Diagnostics | Investigate queue health, traces, execution environments and recovery |

The CLI and optional MCP server use the same dashboard APIs. Existing eve projects can
[attach a dashboard](/docs/cli) or [install individual registry components](/docs/registry).
Eve Stack is a distribution, not a fork of the runtime.

## What you operate

You need Node 24+, Docker and a model provider, or sufficient hardware for a local model.
You maintain service uptime, credentials, backups, upgrades and retention. See
[support](/docs/support) for tested platforms and [backup and restore](/docs/backup-restore)
before storing work you cannot afford to lose.

Eve Stack is Apache-2.0 software without a software subscription fee. Hardware, hosting,
electricity, model usage and connected services may cost money. Prompts reach the configured
model provider. Optional Composio integration is hosted and holds tokens for connected
accounts; external tools receive the data needed for their calls.

## Operating boundaries

- A completed task still needs result and evidence review. Automated correctness is not implied.
- Approvals apply to configured gated tools. Read-only wording in a prompt does not restrict permissions.
- Sandbox isolation depends on the backend, mounts, network and tools you configure.
- Cancellation is cooperative; acceptance does not prove an in-flight call has stopped.
- Shared installation credentials are not individual teammate identities or tenant isolation.
- Unknown routine dispatch pauses for investigation. Repeating uncertain work can duplicate its effects.

The [component manifest](/docs/upgrading) records the selected package and storage versions
for a source checkout. It does not prove those versions have been published or deployed.
The [release plan](https://github.com/SammyTourani/evestack/blob/main/RELEASE_PLAN.md)
distinguishes verified checks from live-provider and pilot gates.
